## Sampling Rate

- **After every task commit:**
  - Run the task's `<automated>` command on Node 24 and the task's new or extended suites under `npx --offline -y node@20`.
  - Run the pin suites for every file the task edits (table below; CONTEXT D-25). Before editing `background.js`, `mcp-bridge-client.js`, `jev-fast-path.js`, `run-bench.mjs` or any test, grep `tests/` for `.match(`, `.includes(`, `indexOf(`, `readFileSync` and `sha256(` pins on that file and bump paired pins in the same commit.
  - Whenever `package.json` or the test chain changes: `node tests/delegation-phase-contract.test.js`.
- **After every plan wave:**
  - The regression sweep over every file edited in the wave against `70-SWEEP-BASELINE.json` (in the background, waited for).
  - Every `tests/jev-*` suite present (67's, 68's and 70's), `node tests/jev-policy-tighten-only.test.js`, `node tests/jev-run-task-upstream-contract.test.js`, and the bridge goldens `node tests/run-task-fast-mode-wire.test.js`.
  - From wave 5: `npm --prefix mcp run build && node --test tests/mcp-run-task-fast-caller.test.mjs && node tests/mcp-tools-list-shape-freeze.test.js`, then `git status --porcelain -- mcp/` must print nothing.
- **Before `/gsd-verify-work` (phase gate, 70-06):**
  - `npm run validate:extension && npm test` is green (run in the background and waited for; it can exceed the 10-minute foreground limit), then `npm --prefix mcp run build && node tests/mcp-tool-smoke.test.js`.
  - `git diff --quiet "$P70_START" -- mcp/` and `git status --porcelain -- mcp/` empty.
  - Every new suite passes under Node 20 (row `ALL-c`).
  - The compatibility audit (row `ALL-a`) is clean.
  - The three showcase crawler files are restored and not committed.
- **Max feedback latency:** 30 seconds per task check. The MCP build (`npm --prefix mcp run build`) runs once per wave; the per-task caller check relies on 69's `assertBuildFresh()` and fails loudly on a stale build rather than rebuilding.
